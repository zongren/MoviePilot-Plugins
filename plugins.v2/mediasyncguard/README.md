# 媒体同步守护（MediaSyncGuard）

监控 Jellyfin 与 qBittorrent，维护媒体文件与下载任务之间的硬链接关系，提供**受控的双向同步删除**和**一次性差异扫描**。

> ⚠️ 本插件会删除文件/种子/媒体库条目，请务必先阅读「安全模型」并保持默认的演练模式，确认扫描结果无误后再开启自动执行。

## 功能特点

- **硬链接精确关联**：按文件系统 inode（`st_dev + st_ino`）把 Jellyfin 媒体条目与 qBittorrent 下载任务关联起来，不依赖文件名猜测；兼容辅种/多站点同文件种子。
- **媒体删除 → 删种**：Jellyfin 中的电影/剧集条目被删除后，自动删除与之关联的下载任务。
- **种子删除 → 删媒体**：qBittorrent 中的下载任务被删除后，自动删除与之关联的 Jellyfin 媒体条目和磁盘文件，并清理字幕、NFO、图片等附属文件与空目录。
- **一次性差异扫描**：扫描「Jellyfin 有媒体、但没有对应下载任务」和「下载器有种子、但没有对应媒体」的条目，在插件页面上勾选后手动删除。
- **默认演练模式**：插件启用后优先只记录/通知候选项，不执行删除；自动删除开关默认全部关闭。
- **多重安全阀**：
  - 自动删除存在可配置的延迟（默认 10 分钟），执行前再次复核，期间可在插件页面取消；
  - 批量保护：一轮内大量媒体/种子同时消失时，视为批量操作或媒体库刷新，跳过自动处理并通知；
  - 忽略分类/标签白名单（默认忽略 `KEEP` 分类）；
  - 删种删文件前检查是否仍有其它种子/媒体引用同一 inode；删媒体前检查是否仍有现存种子引用同一文件；
  - 删除媒体文件只允许发生在配置的「允许删除的媒体根目录」内，且不会碰下载目录；
  - 失败/异常只记录日志与通知，不做兜底性删除。

## 适用前提

1. MoviePilot 已配置 Jellyfin 媒体服务器和 qBittorrent 下载器（插件直接复用 MoviePilot 的服务配置与凭据）。
2. 媒体入库使用**硬链接（link）**整理模式；`move`/`copy` 模式下媒体文件与下载文件没有 inode 关联，只能通过历史记录兜底或扫描页手动处理。
3. Jellyfin 与 qBittorrent 的数据目录在 MoviePilot 容器内可见：
   - 本项目环境：宿主 `/tank/medias` 挂载为 MoviePilot 内 `/medias`；
   - Jellyfin 容器内媒体路径 `/media/...` 通过插件配置 `媒体路径映射`（默认 `/media:/medias`）转换为 MoviePilot 内路径。
4. 若还有**副下载器**（例如数据目录 `/tank/seedings` 未挂载到 MoviePilot 容器），可以在插件中勾选，但插件无法访问其文件做 inode 校验，只会只读展示并给出警告，不会自动删除。

## 使用流程（建议）

1. 安装并启用插件，保持「演练模式」开启、「自动删除」开关关闭。
2. 打开插件管理页，点击「扫描」，等待扫描完成。
3. 查看两个页签的差异结果：
   - **媒体无种子**：Jellyfin 中存在但找不到关联下载任务的媒体（常用于清理历史遗留）；
   - **种子无媒体**：下载器中存在但找不到关联媒体的种子（常用于清理已删除媒体的残留辅种）。
4. 先手动勾选少量条目测试删除，确认行为符合预期。
5. 需要自动化时：
   - 开启「媒体删除 → 自动删除关联种子」，观察一段时间；
   - 再开启「种子删除 → 自动删除关联媒体」；
   - 最后按需关闭「演练模式」。
6. 自动删除触发后，可在管理页的「待执行动作」中查看倒计时并取消（延迟期间内）。

## 安全门禁（v1.0.0 实现）

除了「安全模型」里的删除规则，插件在执行层面还有以下强制门禁：

- **数据源覆盖校验**：配置中选中的每一个 Jellyfin / qBittorrent 服务，只要有一轮没有成功读取，
  本轮就视为“数据不完整”：不生成新的自动删除动作，也不执行已有待办动作（避免复核因缺少数据源变成空判断）。
- **下载器可校验性（插件自身的安全设计）**：如果存在“数据目录在 MoviePilot 容器内不可见”的下载器（例如副QB 的
  `/tank/seedings`），或者存在**已配置但未纳入本插件监控**的下载器（包括暂时在 MoviePilot 设置里禁用的实例），
  插件无法确认“媒体文件是否仍被其它种子引用”，因此会禁用「种子删除 → 自动删除媒体」，并在状态页给出明确警告。
- **手动删除媒体的逐项安全校验**：手动删除媒体时不因“存在未纳管下载器”而一刀切拒绝，而是对每个文件做硬链接引用审计：
  文件 `st_nlink` 必须能被“当前可见的媒体条目 + 可见种子”的引用数完全解释；若 `nlink` 更大（说明存在无法校验的硬链接），
  该条目会被拒绝并提示“无法校验的硬链接”。因此像“BDMV 转码成 MKV、`nlink=1`”的衍生内容可以安全手动删除。
- **删种时的文件删除策略**：未纳管的下载器不再全局禁止删文件。删除种子时，插件只按**可见种子/媒体的 inode 共享关系**
  判断文件能否安全删除：
  - 文件仍被其它现存种子或媒体库硬链接引用 → 保留下载文件（并给出警告）；
  - 无可见引用 → 允许随种子删除下载文件（即使存在未纳管下载器）。
  未纳管下载器如果使用**完全独立的数据目录**（例如副QB 的 `/tank/seedings`），删除主下载目录中的路径不会影响它的做种；
  即使存在跨目录硬链接，删除其中一个链接也不会删除数据本身。如果另一个下载器可能复用**同一物理路径**，请先自行确认或保持
  「联动删除时允许删除磁盘文件」关闭。
- **说明**：以上门禁是本插件为实现安全删除自行加入的逻辑（不是 MoviePilot 的行为），源自独立安全审计；
  目的是防止误删仍被引用的媒体/文件。需要更完整校验时，可把副QB 数据目录只读挂载进 MoviePilot 容器，并在插件配置中同时选中它。
- **多媒体服务器**：如果 MoviePilot 中还有已启用但未被本插件监控的 Jellyfin，插件无法确认媒体是否已在
  其它服务器移除，会自动禁用「媒体删除 → 删种」，并在状态页提示。
- **空数据源保护**：即使配置中“留空=全部服务”在当前环境解析不到任何可用媒体/下载器数据源，
  也不会把“读取不到数据”当成“全部删除”，本轮会标记 partial 并暂停自动处理。
- **手动删除同样受保护**：扫描页的删除操作要求插件处于启用状态、扫描结果不超过 10 分钟、
  单次最多 100 项；执行前会先刷新一轮实时状态，并逐项复核 inode/现存种子/媒体关联，过期或已变化的选择会被拒绝。
- **执行中取消安全**：待执行动作在执行过程中被用户取消，不会因为并发刷新而“复活”。
- **路径安全阀**：自动与手动删除媒体文件都会检查是否位于「允许删除的媒体根目录」且不在下载目录内；
  媒体路径异常（inode 变化、不在允许目录）时拒绝删除。
- **分页完整性**：Jellyfin 返回分页数据时若条目数少于实际总数，直接判定读取失败并按“数据不完整”处理，
  不会把分页截断误判为媒体全部丢失。

## 安全模型

### 媒体删除 → 删种

- 只有**该种子关联的所有媒体条目都从 Jellyfin 消失**后，才会删除种子；多集合集种子不会因为删了其中一集而被整体删除。
- 只有种子状态为已完成/做种中才会进入删除候选；批量保护启动时整批跳过。
- 删除文件前会校验：该种子的视频文件 inode 没有被其它现存种子引用，也没有被媒体库引用；否则只删任务、保留文件。

### 种子删除 → 删媒体

- 只有媒体条目仍在 Jellyfin 中、且**没有其它现存种子引用同一个 inode** 时才会删除（保护辅种场景：删掉一个辅种种子不会误删媒体）。
- 删除媒体时通过 Jellyfin API 删除条目，再清理同目录附属文件与空目录；文件删除范围受「允许删除的媒体根目录」限制。
- 批量保护启动时（例如其它插件批量清理种子）整批跳过，只发通知，避免误删媒体。

### 防误判

- 媒体改名/重新整理：Jellyfin item id 变化但文件 inode 未变时，不算“媒体删除”。
- 下载器/媒体服务器连接失败：不会用空结果覆盖上一轮快照，避免“全量消失”误判；首次运行无基线时不做删除判断。
- 插件重启后的第一轮只建立基线，不处理期间发生的删除；请用扫描页确认。
- 所有自动动作都有动作 ID 去重，不会重复执行。

## 常见问题：为什么有关联的媒体/种子被扫描为“无关联”？

本插件判断“媒体 ↔ 下载任务”关系的**唯一可靠依据是文件系统硬链接的 inode**（其次是 MoviePilot 的整理记录）。
如果媒体文件是从下载内容**转码 / 重新封装 / 压制 / 复制**而来（例如把 BDMV 的 `.m2ts` 转成 `.mkv` 后移动到媒体目录），
即使业务上它们是同一部影视，文件也已经是一个**新的 inode**，不是硬链接：

```bash
stat -c '%i %h' "/tank/medias/TV/示例 (2024)/Specials/示例 - S00E001.mkv"   # links=1 表示没有硬链接
```

这类内容无法被自动关联，因此：
- 扫描会把它们分别列为「媒体无种子」「种子无媒体」；
- 两个方向的自动删除都不会作用于它们（因为没有硬链接关系，插件不会误删）；
- 如果你希望扫描页不再反复提示这些已知的“转码衍生”内容，可在插件配置的**「扫描忽略关键词」**中填入
  媒体路径/目录或种子名称/内容路径的关键词（逗号分隔），例如：
  `Friends Bonus Disc,老友记 (1994)/Specials`
- 反之，如果希望它们真正联动删除，需要让媒体文件与下载文件保持硬链接（整理时使用 link 模式，或对已转码内容手工建立硬链接），
  或者等插件后续提供“手动关联/忽略单条记录”能力。

### 为什么删除种子后提示“保留下载文件”？

旧版本的全局安全门禁在检测到未纳管下载器时会把所有“删除下载文件”请求降级为保留文件。v1.0.1 起改为：
仅当**可见的**其它种子或媒体库仍通过硬链接引用该文件时才保留文件；没有可见引用时会正常删除下载文件。
如果仍看到“与其它种子共享文件/无法校验”的警告，说明该文件在当前可见范围内仍被引用，或者你使用的是旧版本插件，请更新到 v1.0.1。

### 为什么扫描结果会受 qBittorrent 未完成文件影响？

qBittorrent 开启「未完成文件后缀」后，会把未完成文件命名为 `xxx.mkv.!qB`（或 `.!ut`/`.part` 等）。
如果媒体库文件与它是硬链接，它们仍然是**同一 inode**；v1.0.2 起插件会先去掉这些下载器临时后缀再判断视频类型，
因此能够正确识别这种关联，不再把对应媒体/种子误报为“无关联”。如果你的 qB 正在重新校验某个种子，
对应媒体在扫描页短暂消失/出现属于正常现象，以文件系统 inode 为准。

## 限制与说明

- 仅支持 **Jellyfin** 媒体服务器和 **qBittorrent** 下载器（其他类型不会出现在选项中）。
- 依赖硬链接整理（MoviePilot 转移模式 `link`）。`move`/`copy` 入库的媒体无法用 inode 精确关联，只会出现在扫描页由你手动判断。
- 副QB/宿主机其它未挂载到 MoviePilot 的下载目录，插件无法读取文件 inode，只能只读展示（不会自动处理）。
- 一次扫描需要遍历下载目录并读取 Jellyfin 条目，媒体库很大时耗时与磁盘 IO 会增加；扫描在后台线程执行，不会阻塞 MoviePilot。
- 插件不保存 Jellyfin/qB 凭据，运行时直接读取 MoviePilot 的媒体服务器/下载器配置。

## 下载器临时 / 残留文件

一次性扫描新增「下载器临时文件」页，用于发现下载目录中的 `.!qB` / `.!ut` / `.part` 等文件：

- 插件会读取现存任务的**文件清单**，判断每个临时文件是否仍属于某个当前任务；
- 仍属于现存任务的文件会显示归属任务并**禁止删除**（删除会破坏该任务的数据）；
- 不属于任何现存任务的“无主残留”可以勾选清理；
- 归属校验失败（例如任务文件清单读取失败）的文件也会禁止删除，避免误伤。

注意：qBittorrent 开启「未完成文件后缀」时，正在校验/未完成的文件会以 `xxx.mkv.!qB` 形式存在，
这种文件通常是**现存任务的未完成数据**，不是垃圾文件；如果确认任务已删除，它才会变成可清理的残留。
